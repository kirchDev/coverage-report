# Add a coverage format

Four formats ship: lcov, Cobertura, Clover and Istanbul `coverage-final.json`. A fifth — JaCoCo, Go's `cover` profile, SimpleCov's JSON — is a parser plus a detection rule, and nothing else: everything downstream works on [the report model](../1.concepts/1.the-report-model.md) and never learns that a new format exists.

## Steps

1. **Get a real report first.** Not a hand-written sample — run the tool that produces the format against a project with genuinely partial coverage, and keep the file. A fixture invented from the specification will agree with your parser and with nothing else.

2. **Write the parser** in `src/parsers/{format}.js`. It takes the file's text plus `{ root, sourceRoots }` and returns a report. Record every key, then record hits separately, so a file with no coverage stays in the total:

   ```js
   const file = fileOf(report, normalisePath(path, options));
   recordKey(file.lines, lineNumber); // the line exists
   recordHits(file.lines, lineNumber, hits); // and this many times it ran
   ```

   For an XML format use `scanTags` from `src/parsers/xml.js` rather than adding a parser dependency — it walks tags in document order and hands back their attributes, which is all Cobertura and Clover need.

3. **Register it** in `src/parsers/index.js`: add the name to `FORMATS`, the function to `PARSERS`, and a rule to `detectFormat`. Detection reads the first few kilobytes of content and never the file name — `coverage.xml` is Clover in a Laravel repo and Cobertura in a .NET one. If the new format also opens with a tag an existing one uses, the rule has to distinguish them on a child element, the way Clover and Cobertura are told apart.

4. **Prove it against the numbers the producing tool printed.** Add the trimmed real report to `test/fixtures/` and assert the totals the tool itself reported for that run. This is the only check that catches a parser which is self-consistent and wrong.

5. **Prove it agrees with another format.** If the same run can be exported twice, assert both exports produce the same line total — that is the test that caught Clover counting method declarations as statements.

6. **Rebuild the bundle** with `pnpm build` and commit `dist/index.js` in the same commit, or `pnpm check:dist` fails.

## Checklist

- [ ] `coverage-report detect <file>` names the new format on a real report.
- [ ] Totals match what the producing tool printed for that run.
- [ ] A second export of the same run reports the same line total, where one exists.
- [ ] A file with zero coverage appears in the total rather than vanishing from it.
- [ ] No new runtime dependency ([ADR-0003](../99.adr/0003-ship-the-action-with-almost-no-dependencies.md)).
- [ ] `pnpm check` passes, `dist/index.js` rebuilt and committed.
