# The report model

lcov, Cobertura, Clover and Istanbul disagree about almost everything: what a line record looks like, whether branches carry identity, whether paths are absolute, whether a method declaration is a statement. A tool that keeps those differences alive needs a merge routine per pair of formats. This one reduces all four to a single shape on the way in, and then never thinks about formats again.

## How it works

A report is a map of repository-relative path to a file, and a file holds three maps of **key to hit count** — one for lines, one for branches, one for functions.

The keys differ per metric, because that is what the formats give us:

- **lines** — the line number
- **branches** — `line:index`, so two reports of the same file agree on which branch is which
- **functions** — `line:name`, since a name alone is not unique within a file

Everything downstream reads one thing off that: `covered` is the number of keys whose hit count is above zero, `total` is the number of keys. Merging two reports is therefore the union of their keys with hit counts summed — one operation, identical for all three metrics, with no format knowledge anywhere in it.

Two consequences fall out of the shape rather than being coded for. A line executed by both the unit suite and the component suite is one key, so it counts once and cannot inflate the denominator — a repository cannot raise its coverage by splitting a suite. And a key recorded with zero hits is still a key, which is what keeps an entirely untested file in the total rather than silently absent from it.

## Why it's built this way

**Paths are normalised before anything else touches them**, because the merge is keyed on the path: two reports that spell the same file differently merge into two files, and the total is then wrong in the direction that looks healthy — more files, a bigger denominator, no error anywhere. Normalisation runs on strings rather than through `node:path`, which resolves against the host and would read a Windows path as a relative one when the same report is inspected on Linux.

**A file with nothing to measure counts as fully covered.** The alternative drags the total down every time an empty barrel file is added, which punishes exactly the change that should be free.

**Two format-level judgements were made so that one test run yields one number regardless of which reporter wrote it.** A Clover `type="method"` line is recorded as a function and not as a statement — PHPUnit counts method declarations in its `elements` total but not in `statements`, and Cobertura emits no line for them at all, so counting them would make the same run report 809 lines as Clover and 763 as Cobertura. And a function counts as covered when it ran at least once, which is what lcov, Cobertura and Istanbul all mean by it; PHPUnit's own `coveredmethods` instead requires every line in the method to be covered, so its figure is deliberately not reproduced.

**An Istanbul `coverage-summary.json` is refused rather than read.** It carries per-file totals and no line numbers, so it can answer neither of the questions this tool exists for. Read leniently it yields a report with zero lines in it — and zero of zero is 100%, which would take a run that measured nothing and turn it green. The loud failure is the feature.
